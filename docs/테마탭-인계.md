## 0. 먼저 알아야 할 것

**API 키는 넘기지 않는다.** 받는 쪽에서 직접 발급해야 한다.

| 키 | 발급처 | 쓰는 곳 |
|---|---|---|
| `DART_API_KEY` | opendart.fss.or.kr (무료, 즉시) | 사업보고서·재무제표 수집 |
| `KIS_APP_KEY` / `KIS_APP_SECRET` | 한국투자증권 오픈API | 시세·시가총액·PER |

코스콤 키는 계약 당사자의 것이므로 외부에 넘길 수 없다. 외주 인력에게는
샌드박스 키를 쓰게 할 것.

`.env.local` 과 `.kis-token.json` 은 gitignore 다. 저장소에 없다.

## 3. 무엇을 만든 것인가

에프앤가이드 테마 분류를 사지 않고 **DART 사업보고서(공공데이터)로 직접
만든 것**이다. 지금 상태:

```
테마          91개
편입 종목      2,497 / 상장 2,758  (90%)
응집도        0.482  (에프앤가이드 0.493 대비 98%)
              무작위 묶음 대비 올린 폭으로는 107%
겹침          평균 1.71개 · 4개 이상 160종목
```

**응집도**란 테마 안 종목들이 실제로 같이 움직이는지를 잰 것이다. 테마 안
종목쌍의 일간 수익률 상관을 재고, 시장에서 아무렇게나 뽑은 같은 크기 묶음과
견준다. 자세한 것은 `scripts/theme/evaluate.mjs` 의 머리말에 적어 두었다.

### 권리 관계

| 무엇 | 어디서 | 조건 |
|---|---|---|
| 테마 분류 · 편입 사유 | SIGNO 자체 (DART 사업보고서 기반) | 우리 것 |
| 매출성장 · 영업이익률 | DART 공공데이터 | 공공데이터법 준칙 — 상업적 이용 가능 |
| 시세 · 시가총액 · PER | KIS (계약) | 계약 범위 안에서 |

에프앤가이드에 기대는 것은 하나도 없다. `baseline.json` 은 성능을 견주려고
한 번 재어 둔 수치일 뿐 서비스에 쓰이지 않는다.

## 5. 파이프라인 — 순서를 지켜야 한다

`src/data/themes.json` 을 다시 만드는 차례다. 앞 단계 결과를 뒷 단계가
읽으므로 순서가 틀리면 조용히 어긋난다.

```bash
node scripts/theme/collect.mjs          # DART 사업보고서 → overview.json   (6시간)
node scripts/theme/collect-sales.mjs --all   # 부문별 매출 → sales.json      (25분)
node scripts/theme/collect-revenue.mjs       # 총매출액 → revenue.json       (15분)
node scripts/theme/collect-fin.mjs           # 재무 → fin.json

node scripts/theme/build-df.mjs         # 낱말 빈도 → df.json
node scripts/theme/classify.mjs         # 규칙 분류 → classified.json
node scripts/theme/ingest-xlsx.mjs <작업지.xlsx>   # 사람 문장 → manual.json
node scripts/theme/tidy-why.mjs --write      # 군더더기 제거
node scripts/theme/strip-opinion.mjs --write # 투자 평가 제거
node scripts/theme/apply-manual.mjs     # 사람 것을 규칙 위에 얹는다
node scripts/theme/apply-sales.mjs      # 곁가지 사업 테마를 뗀다
node scripts/theme/build-data.mjs       # → src/data/themes.json

node scripts/theme/evaluate.mjs         # 응집도 (report-doc.txt 도 남긴다)
node scripts/theme/separation.mjs       # 분리도
node scripts/theme/doc-data.mjs && python scripts/theme/make-pdf.py       # 기준서 PDF
node scripts/theme/doc-all.mjs && python scripts/theme/make-pdf-all.py    # 작업지 PDF
```

수집(위 넷)은 이미 받아 놓은 것이 있으면 건너뛰어도 된다. 사업보고서는 1년에
한 번 바뀐다.

**PDF 를 다시 뽑을 때는 `evaluate.mjs` 를 먼저 돌릴 것.** 기준서가
`report-doc.txt` 에서 응집도를 긁어 가는데, 그 파일이 없으면 옛날 수치가
그대로 인쇄된다(실제로 한 번 그랬다).

## 6. 반드시 알아야 할 함정

여기 적은 것은 전부 실제로 겪은 것이다.

### 6.1 DART 를 조이면 IP 가 막힌다

동시 8로 올렸다가 262종목에서 끊겼다. `CONC = 2` · `PAUSE = 400ms` 를
지킬 것. 연속 실패 12번이면 멈추고, 다시 실행하면 이어서 받는다.

### 6.2 "본문 없음"(status 014) 과 통신 실패는 다르다

`[첨부정정]` 보고서에는 본문이 없다. 이걸 통신 실패로 세면 연속 실패
카운터가 차서 수집이 통째로 멈춘다. 후보 보고서를 4개까지 내려가며 시도한다.

### 6.3 인코딩은 XML 선언을 보고 정한다

한글 개수로 추정하면 틀린다. UTF-8 파일을 EUC-KR 로 읽어도 `/사업/` 검사가
우연히 통과해서, 웹젠이 2,000자 대신 400자만 들어왔다.

### 6.4 표를 문장으로 읽으면 안 된다

사업보고서에는 표를 한 줄로 풀어 놓은 것이 아주 많다. 그것을 문장으로 읽으면
한 회사가 온갖 테마에 붙는다.

```
킵스파마  "사업부문 주요사업분야 주요제품 관련회사 비고 제약·바이오 …"
          → 이 한 줄로 폐배터리 재활용·OLED·비만치료제가 한꺼번에 붙었다
```

숫자가 많은 표는 자릿수 비율로 거른다. **숫자가 없는 표**는 조사 밀도로
거른다 — 진짜 문장은 조사가 촘촘하고 표는 이름만 나열한다(문턱 0.4).
`classify.mjs` 의 `looksTable` · `글로된표` 참고.

### 6.5 흔한 낱말은 혼자 서지 못한다

"시공" 은 보고서 3,035건 중 226건에 나온다. 생산라인을 들이는 회사면 어디든
적는 말이라 이것 하나로 건설사라고 할 수 없었다. 그래서 건설·건축에 갈매기
프랜차이즈와 자동차부품사가 들어와 있었다.

낱말 빈도(`df.json`)로 무게를 달리 준다.

```
드문 낱말(2% 미만)   3점 → 하나로 편입
보통(2~5%)          2점 → 하나 더 필요
흔한 낱말(5% 넘음)   1점 → 셋 필요
```

### 6.6 작업지의 "서브테마" 칸은 사람 판단이 아니다

그 칸은 **우리 규칙이 채워 넣은 것**이고, 대표는 설명만 쓰고 그 칸은 그대로
두었다. 그것을 "사람이 확인함"(99점)으로 받으면 규칙의 잘못이 굳어 나중에
규칙을 고쳐도 안 풀린다.

```
오르비텍  설명 "항공·방산 부품 정비를 영위하는 기업이다"
          칸   의료기기 · 핀테크·결제 · 태양광 · 원자력 · 풍력 · 2차전지 장비
```

지금은 **사람이 쓴 설명이 뒷받침할 때만** 칸을 받는다. 1,105행 중 584행을
물렸다. 작업지를 새로 받을 때도 이 규칙을 유지할 것.

### 6.7 매출 표 파싱은 반드시 밖에서 검증한다

부문별 매출로 곁가지 테마를 떼는데(`apply-sales.mjs`), 파서가 틀리면 멀쩡한
테마가 날아간다. 눈으로 고른 잣대만 썼을 때 **떼어 낸 25건 중 절반이
틀렸다** — 서울반도체의 LED, 명문제약의 제약이 떨어졌다.

지금은 빗장이 넷이다.

1. 표에 적힌 단위(`(단위 : 백만원)`)를 읽고, **부문값 × 단위 ÷ 실매출** 로 낸다
   (표에서 더한 합을 분모로 쓰면 3년치가 겹쳐 453종목에서 3.16배 부풀었다)
2. 한 부문이 90% 를 넘으면 그것은 부문이 아니라 합계다 → 그 종목은 손대지 않는다
3. 비중 합이 0.75~1.5 밖이면 잘못 읽은 것이다
4. 붙어 있는 테마 중 하나라도 큰 부문(25% 이상)과 맞아야 뗀다
   — 그래야 "주력은 저것이고 이것은 곁가지" 라고 말할 수 있다

이 빗장들 때문에 2,492종목을 걷어 9건만 뗐다. **수확이 작은 것은 의도한
것이다.** 데이터를 지우는 장치이므로 적게 떼더라도 틀리게 떼지 않는 쪽을
골랐다. 문턱을 낮추려면 반드시 `sales-dropped.json` 을 눈으로 확인할 것.

### 6.8 장 시작 전 KIS 는 등락률을 0 으로 준다

현재가 == 전일종가로 오므로 모든 테마가 0% 가 된다. 마지막 세션 값을
스냅샷으로 두고, 움직인 종목이 200개 미만이면 스냅샷을 쓴다
(`ownTheme.ts` 의 `SNAP_KEY`).

### 6.9 상한가를 넘는 등락률은 데이터 오류다

헝셩그룹이 +400% 로 들어와 화장품 브랜드 테마 평균이 +22% 가 됐다.
KRX 제한폭 ±30.5% 를 넘으면 버린다(`LIMIT`).

### 6.10 캐시 키에 커밋 SHA 가 붙는다

`cached(key, ttl, fn)` 는 배포마다 캐시를 버린다. 사업보고서처럼 배포와
무관한 데이터는 `{ global: true }` 를 줘야 한다. 안 그러면 배포할 때마다
23초씩 걸린다.

### 6.11 `npm --prefix` 는 작업 폴더를 바꾸지 않는다

`npm --prefix C:\signo run dev` 로 띄우면 API 라우트가 전부 404 다.
`cmd /c cd /d C:\signo && npm run dev` 로 할 것.

## 7. 남은 일

### 7.1 겹침 4개 이상 160종목

```
킵스파마     8개  신약 개발 · 금속가공 · OLED · 방위산업 · 포장재
코오롱       9개  소프트웨어 · 건설 · 의류 · 섬유 · 지주회사
```

이 회사들은 **실제로 여러 사업을 한다.** 문제는 "사실이냐" 가 아니라
"그 종목의 정체냐" 이다. 매출 비중으로는 더 못 푼다 — 이들의 매출 표는
"제품매출/상품매출" 로만 나뉘어 근거가 없다.

작업지에 이 160종목만 뽑아 주력 사업을 한 줄씩 받는 것이 가장 빠르다.

### 7.2 작업지 미배정 163종목

`manual-unmatched.json`. 사람이 쓴 설명은 있는데 테마를 못 고른 것들이다.

### 7.3 분리도가 낮은 테마

`separation.mjs` 로 재어 둔 것이 `NEXT.md` 에 있다. 요지:

- **보안·경비** 잔차 -0.020 — 91개 중 유일한 음수. 없애는 쪽이 맞다
- **메모리 반도체 ↔ HBM 밸류체인** 교차 0.495 — 사실상 한 테마다
- 전자부품 대분류(커넥터·MLCC·OLED·팹리스)가 전부 메모리 반도체로 빨린다

응집도만 보고 손대면 안 된다. 음식료는 응집도 하위권인데 분리도는 3위다.

### 7.4 편입 사유가 56% 뿐

나머지는 비워 두었다. 사업보고서에서 쓸 만한 문장을 못 뽑은 경우인데,
표 덤프나 업계 전망을 억지로 채우는 것보다 비우는 편이 낫다고 판단했다.
작업지를 더 채우면 올라간다.
