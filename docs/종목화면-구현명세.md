# 종목 화면 구현 명세 — 법인 앱

**차트 탭은 손대지 않고 정보 탭을 목업처럼 다시 짜기 위한** 명세다.
블록 순서대로 적었고, 각 블록마다 **무엇을 그리나 · 어디서 받나 · 다 됐다고
볼 조건**을 붙였다.

기준 API 는 SIGNO(`signo-chi.vercel.app`) 것이고, 응답은 2026-08-31
셀트리온(068270)에서 실제로 받은 값이다. 코스콤으로 갈아끼우는 방법은
`README.md`(PORTING-STOCK-TAB), 두 앱을 어떻게 나눌지는 `합치기-명세.md`.

---

## 0. 어디를 손대나

**차트 탭은 손대지 않는다.** 지금 그대로 둔다 — 차트 + 성장점수 신호등.
**정보 탭을 목업처럼 다시 짠다.**

```
헤더            종목명 · 코드 · 현재가 · 테마칩 · ★        ← 점수 배지만 뺀다
탭              차트 / 정보 / 뉴스 / AI                    ← 그대로

차트 탭         차트(봉주기·지표·드로잉·지지저항)            ← 그대로
                성장점수 신호등                             ← 그대로

정보 탭 ─────────────────────────────────────────────
  1  종목 개요       주요사업 · 평가 · 모멘텀      ← 새로 붙임 (SIGNO)
  2  종목 상세       수급 · 기간수익률 · 지표 12칸  ← 새로 붙임 (SIGNO)
                     기존 '기업 정보' 카드를 이것이 대신한다
  3  재무제표        연간/분기 · 컨센서스           ← 새로 붙임 (SIGNO)
  4  투자자별 매매동향                              ← 그대로
  5  유동물량        상장·유통 주식수 · 유통비율     ← 그대로
  6  대주주 현황     상위 5                        ← 그대로
  7  섹터 종합평가   등급 · 7개 항목 · 업종 상위 10  ← 새로 붙임 (SIGNO)
```

**재무 신호등(성장점수)은 정보 탭에 넣지 않는다.** 차트 탭에 이미 있다.
같은 것을 두 탭에 두면 어느 쪽이 최신인지 헷갈린다.

대신 신호등의 `[상세보기]` 버튼이 **정보 탭의 재무제표로 바로 가게** 한다.
탭을 정보로 바꾸고 재무제표 블록까지 스크롤한다(§5).

### 수급이 앞으로 온 이유

`투자자별 매매동향`이 재무제표 바로 뒤다. 물량·지분(유동물량·대주주)보다
매매동향을 먼저 본다는 뜻이다. 앞의 세 블록이 "이 회사가 어떤가" 라면
4번부터는 "누가 사고 있나" 이고, 그 안에서도 오늘 움직이는 것이 먼저다.

`수급 추이 30일` 은 매매동향에 딸린 표다. 지금처럼 그 바로 아래 둔다.

### 기존 '기업 정보' 카드는 없앤다

지금 정보 탭 맨 위의 기업 정보 카드는 새 '종목 상세'와 거의 겹친다.

```
기업 정보(지금)   시가총액 · 52주 최고/최저 · PER · PBR · EPS · 배당수익률 · 섹터 · 테마
종목 상세(새것)   위의 것 전부 + BPS · 외국인비율 · 목표주가 · 투자의견 · 추정PER
                  + 최근 5거래일 수급 + 기간수익률 5칸
```

같은 값을 두 번 보여줄 이유가 없다. 다만 두 줄은 갈 곳을 따로 정한다.

| 기업 정보의 줄 | 어디로 |
|---|---|
| 시총·52주·PER·PBR·EPS·배당 | 종목 상세가 그대로 받는다 (52주는 여기서 채워진다) |
| 섹터 | 종목 상세 카드 머리에 종목명과 함께 |
| 테마 | **헤더 칩으로 올린다** (§1) — 목업이 그렇게 되어 있다 |

## 1. 헤더

```
셀트리온  [코스피]  068270 ▾                              ★
190,400  ↘ -0.47% (-900원)      바이오시밀러 -0.05%
```

- 종목명 옆 `▾` 를 누르면 종목 검색이 열린다
- `★` 는 관심종목 담기 (기존 동작 그대로)
- **점수 배지는 넣지 않는다.** 목업에는 원형 `98` 이 있었으나 빼기로 했다.
  성장점수(98)와 종합평가(66)가 한 화면에 나란히 뜨면 어느 쪽을 봐야 하는지
  알 수 없다. 두 점수는 각자 제자리에서 이름을 달고 뜬다.

### 테마 칩

```
바이오시밀러 -0.05%
```

`GET /api/stock-themes?code=068270` → SIGNO 테마 분류.
지금 정보 탭의 "테마" 자리에는 표준산업분류(`기초 의약물질 및 생물학적 제제
제조업`)가 들어가 있다. 그것을 이 값으로 바꾼다.

숫자는 그 테마 구성종목의 오늘 등락률 평균이다. 칩을 누르면 같은 테마
종목 목록으로 간다.

**데이터는 `src/data/themes.json` 한 파일에 다 있다.** 이 꾸러미의
`src-snapshot/src/data/themes.json` 이 그것이고, 저장소에도 커밋되어 있다.
시세도 키도 다른 꾸러미도 필요 없다 — 파일만 옮기면 그대로 돈다.

분류를 **다시 만들** 생각이 있을 때만 테마 꾸러미(`SIGNO-테마탭-인계.zip`)가
필요하다. 거기에 DART 사업보고서 원본과 파이프라인이 들어 있다. 쓰기만 할
거면 이 꾸러미로 충분하다.

> 됐다고 볼 조건 — 셀트리온에서 `바이오시밀러`, 삼성바이오로직스에서
> `바이오 CDMO` 가 뜬다. 표준산업분류 문구가 화면 어디에도 남아 있지 않다.

## 2. 차트

기존 구현을 그대로 쓴다. 목업과 다른 점만 적는다.

```
봉주기   5분 15분 30분 1시간 4시간 일 주 월        (그대로)
지표     SMA(1)▾  BB  RSI  MACD | 패턴(12) | 추세선  FVG  OB   (그대로)
드로잉   추세선 연장선 수평선 수직선 박스 텍스트 측정 복사 지우기  (그대로)
지지저항 저항2 211,326 · 저항1 193,969 · 지지1 184,143 …        (그대로)
읽기줄   26년 8월 28일 시 190,700 고 190,700 저 187,600 종 190,400
         등락 -900(-0.47%) 거 337.21k                          (그대로)
```

지지·저항 표시는 **켜고 끄는 버튼이 이미 있다**(툴바 오른쪽 끝). 잘 도는
것을 확인했으므로 새로 만들 것이 없다.

## 3. 기업 개요 — 이 회사가 무슨 일을 하는가  ← 새로 붙임

```
셀트리온 개요
  · 항체 바이오시밀러(특허 만료된 바이오의약품의 복제약)를 개발·생산해
    미국·유럽 등 글로벌 시장에 직접 판매하는 국내 대표 바이오기업이다.
  · 생명공학기술을 기반으로 자가면역질환, 종양 등 질병의 치료에 사용되는
    의약품을 개발 및 상업화하는 것을 주요 목적 사업으로 하는 글로벌
    생명공학기업이다.
  · 2023년 12월 ㈜셀트리온헬스케어와의 합병을 통해 개발, 생산, 판매가
    결합된 통합 법인 체제를 완성했다.

  [바이오시밀러 5종목]
```

### 여기에 숫자를 넣지 않는다

처음에는 이 카드에 평가(점수·매출성장·이익률·PER·목표주가·의견)와
모멘텀(1개월·이평선·외국인)까지 넣었다가 걷어냈다. 그 값이 하나도
빠짐없이 아래 카드에 또 있었기 때문이다.

| 개요에 있던 것 | 실제로 있는 곳 |
|---|---|
| SIGNO 점수 · 골든크로스 | 섹터 종합평가 |
| 매출성장 · 영업이익률 | 재무제표 |
| PER · 시총 · 목표주가 · 의견 | 종목 상세 |
| 1개월 · 외국인 | 종목 상세 |

같은 숫자를 두 번 보여 주느라 정작 "이게 뭐 하는 회사냐" 가 묻혔다.
차트와 호가보다 이 카드가 먼저 오는 이유는 처음 보는 종목에서
"무슨 회사인가" 가 먼저이고, 그 답이 없으면 아래 숫자들이 다
의미가 없어서다.

### 문장은 어디서 오나

지어내지 않는다. **DART 사업보고서 '사업의 내용 — 사업의 개요' 원문에서
문장을 골라 옮긴 것**이다. 어미만 평서체로 맞추고 뜻은 건드리지 않는다.

증권플러스·네이버의 기업개요도 결국 같은 원문을 줄인 것이므로 따로
사 올 것이 없다.

  만드는 곳   `scripts/theme/build-about.mjs` (분기에 한 번)
  결과        `src/data/about.json`  code → 문장 배열
  커버리지    2,497종목 중 2,367종목(94.8%) · 종목당 평균 2.7문장

고를 때 거르는 것 — 표를 한 줄로 풀어 놓은 것, 업계 전망·시장 규모,
**실적 숫자(재무제표 카드에 있다)**, 지분·주주총회·공시 절차,
하려는 일(계획·예정), 소제목이 앞에 붙어 온 것, 종속회사 소개.

### 받는 곳

`GET /api/stock-brief?code=068270`

```json
{
  "name": "셀트리온",
  "about": [
    "항체 바이오시밀러(특허 만료된 바이오의약품의 복제약)를 개발·생산해 …",
    "생명공학기술을 기반으로 자가면역질환, 종양 등 …",
    "2023년 12월 ㈜셀트리온헬스케어와의 합병을 통해 …"
  ],
  "why": "항체 바이오시밀러(…)를 개발·생산해 … 국내 대표 바이오기업이다.",
  "biz": ["항체 바이오시밀러", "특허 만료된 바이오의약품의 복제약"],
  "themeName": "바이오시밀러",
  "themeCount": 5
}
```

| 화면 | 필드 | 비고 |
|---|---|---|
| 개요 문장 | `about[]` | 없으면(5%) `why` 한 줄로 대신한다 |
| 주요사업 낱말 | `biz[]` | **문장에 없는 것만** 칩으로 단다(아래) |
| 테마 N종목 | `themeName` `themeCount` | 가장 좁은 테마 하나 |
| 카드 제목 | `name` | 주소에 이름 없이 들어왔을 때만 쓴다 |

**이 주소는 바깥을 하나도 부르지 않는다.** 전부 배포에 실린 표에서
읽으므로 몇 밀리초에 답한다. 예전에는 여기서 시세·일봉 270개·시장
기준선까지 받았는데, 그 값들을 개요에서 걷어낸 뒤로는 아무도 쓰지 않는
것을 받자고 네 군데를 두드리고 있었다. 숫자가 필요하면 그것을 보여 주는
카드가 따로 부른다.

### 규칙 세 가지

**주요사업 낱말은 문장에 없는 것만 남긴다.** 낱말은 개요 문장에서 뽑아낸
것이라 99.5%가 문장 안에 그대로 들어 있다. 바로 위에 쓰인 말을 칩으로
또 다는 것은 군더더기다. 개요가 없어 칩만 서는 종목에서는 다 남는다.

**개요도 낱말도 없으면 카드째 숨긴다.** 제목만 남은 빈 상자는 고장난
것처럼 보인다.

**뼈대(로딩 자리표시)를 카드와 같은 색으로 두지 않는다.** 카드가
`bg-surface` 인데 뼈대도 `bg-surface` 로 두었더니 받는 동안 화면에
빈 상자만 서 있었다. `bg-line/60` 처럼 한 단계 다른 색을 쓴다.

> 됐다고 볼 조건 — 셀트리온에서 문장 셋이 서고 낱말 칩은 하나도 안
> 뜬다(둘 다 문장 안에 있다). 개요가 없는 종목(예: 에스넷 038680)에서는
> 편입 사유 한 줄이 대신 뜬다. 우리 분류표에 없는 종목(예: 팅크웨어
> 084730)에서는 카드가 통째로 없다.

채워 준다. 일봉만 있으면 계산되는 값이라 따로 받을 필요도 없다.

> 됐다고 볼 조건 — 12칸이 다 차고, 52주 최고/최저에 숫자가 들어간다.
> 수급 배지가 `기관 매수우위` / `외국인 매수우위` / `개인 매수우위` 중
> 하나로 뜬다.

### 받는 곳

`GET /api/financials?code=068270`

```json
{
  "periods": [
    { "title": "2023.12.", "cns": false },
    { "title": "2026.12.", "cns": true }
  ],
  "rows": [
    { "title": "매출액", "values": ["21,764", "35,573", "41,625", "55,304"] }
  ]
}
```

`cns: true` 인 열이 컨센서스(추정)다. 머리글에 `E` 를 붙이고 색을 달리해
실적과 구분한다. 구분하지 않으면 추정치를 실적으로 읽는다.

위쪽 가이던스 카드는 마지막 열(추정)과 그 앞 열(실적)의 차이로 만든다.
`%p` 는 비율 항목(영업이익률·ROE)에만 쓴다.

`-` 는 그 기간에 값이 없다는 뜻이므로 0 으로 바꾸지 않는다.

> 됐다고 볼 조건 — 연간/분기 토글이 돌고, 추정 열이 눈으로 구분되며,
> 부채비율 2026.12.E 자리가 `-` 로 남아 있다.

### 차트 탭 신호등의 [상세보기] 가 여기로 온다

차트 탭 재무 신호등의 `[상세보기]` 를 누르면 **정보 탭으로 바꾸고 이 블록까지
스크롤**한다. 지금은 그 버튼이 어디로 가는지 정해져 있지 않다.

```
누르면   탭 = 정보  →  재무제표 블록으로 스크롤
```

블록에 앵커(예: `id="financials"`)를 달아 두면 다른 데서도 부를 수 있다.

> 됐다고 볼 조건 — 차트 탭에서 [상세보기] 를 누르면 정보 탭 재무제표가
> 화면에 들어와 있다. 탭만 바뀌고 맨 위에 머무르면 안 된다.

### 알아야 할 것 셋

**1. 비교군은 둘이다.** `groups` 에 업종(제약)과 테마(바이오시밀러)가 온다.
칩으로 바꿔 끼우면 순위가 다시 매겨진다. 테마 비교군은 SIGNO 분류를 쓰므로
`themes.json` 이 있어야 한다.

**2. 점수는 비교군과 무관하다.** 시장 전체(시총 상위 100종목) 분포 기준이라
비교군을 바꿔도 66점은 그대로고 **순위만 바뀐다.** 화면 아래에 이 문장을
적어 두는 편이 낫다 — 안 적으면 "비교군 바꿨는데 점수가 왜 그대로냐" 는
질문이 반드시 나온다.

**3. `baseline.ready` 가 false 면 점수를 못 낸다.** 지표 크론이 시장 분포를
아직 못 채운 상태다(`samples < need`). 이때는 카드를 통째로 숨긴다. 0점이나
빈 막대를 그리면 안 된다.

### 이 블록만 준비가 다르다

앞의 세 블록(개요·상세·재무제표)은 한 종목만 부르면 되는데, 이건 **비교군
전체의 재무가 필요하다.** 15종목이면 DART 를 15번 두드려야 하고, 화면을 열
때마다 그러면 하루 2만 건 제한에 금방 걸린다.

SIGNO 는 크론으로 미리 쌓아 두고 화면은 읽기만 한다.

```
/api/cron/metrics   종목별 지표를 모아 Redis 에 쌓는다 (lib/baseline.ts)
화면                쌓인 것만 읽는다 — DART 를 직접 부르지 않는다
```

같은 구조가 없으면 이 블록은 붙이지 않는 편이 낫다. 자세한 것은
`README.md` §7 의 "sectorRank 를 만들 때".

> 됐다고 볼 조건 — 비교군 칩을 바꾸면 순위와 목록이 바뀌고 점수는 그대로다.
> 상위 목록에서 다른 종목을 누르면 그 종목 화면으로 간다. 지표 크론을 돌리기
> 전에는 카드가 아예 안 보인다.

## 8. 붙이는 순서

앞이 될수록 값싸고 눈에 띄는 변화가 크다.

```
1  테마 칩 교체         themes.json 만 있으면 된다. 키·시세 불필요      (반나절)
                        헤더로 올리고, 기업 정보의 테마 줄은 지운다
2  종목 상세로 교체      기업 정보 카드를 종목 상세로 갈아 끼운다         (1~2일)
                        52주 최고/최저가 여기서 채워진다
3  기업 개요            정보 탭 맨 위. stock-brief 한 번(바깥 호출 없음)  (1일)
4  재무제표             financials + 가이던스 카드                     (2~3일)
                        + 차트 탭 [상세보기] 딥링크 (§5)
5  섹터 종합평가        sector-rank + 지표 크론                        (1주 이상)
```

1·2 는 데이터가 이미 있어 바로 된다.
3·4 는 코스콤이 못 주는 항목(재무·컨센서스)이 섞여 있어 DART 키가 필요하다.

**5 만 성격이 다르다.** 비교군 전체의 재무가 필요해 지표 크론을 먼저 세워야
한다(§6). 크론 없이 붙이면 화면 한 번 열 때마다 DART 를 열댓 번 두드리게 되고,
하루 2만 건 제한에 금방 걸린다. 1~4 를 먼저 내보내고 5 는 뒤에 붙여도 된다.
